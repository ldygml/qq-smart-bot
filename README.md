# 给她爱：QQ 智能聊天机器人

“给她爱”是一个运行在 Windows 本机的 QQ AI 机器人。它通过 NapCat 接入 QQ 个人号，
使用阿里云百炼千问完成聊天、联网搜索、图片理解、文件总结和语音识别。

项目不只是“自动回复”：它维护短期聊天上下文、跨联系人的长期记忆、关系反思和成长
笔记，并配有开机手动启动、关闭、群聊免 @、群聊必须 @ 等一键脚本。

> **风险提示**
>
> 个人 QQ 号自动收发消息不属于 QQ 官方机器人接入方式，可能触发平台风控。建议只在
> 备用小号上运行，不要批量加人、营销或高频群发。需要长期稳定运营时，应使用
> [QQ 开放平台](https://q.qq.com/) 的官方机器人。

## 已实现功能

### 1. 真人化聊天人格

- 机器人人格名为“给她爱”，是一个有足球偏好、有脾气和判断的普通聊天对象。
- 足球只在对方聊体育、询问爱好或自我介绍时出现，不会把无关话题硬扯到足球。
- 普通闲聊短句、口语化，不默认写总结、列清单或输出客服模板。
- 会根据联系人、历史聊天和当前情绪调整语气。
- 可以冷嘲、拆台和直接指出问题，但不使用脏话、威胁、歧视或身份羞辱。
- 不主动声明“我是助手”；被直接询问时如实说明自己是 AI。
- 完整人格文件：[prompts/gexiai.md](prompts/gexiai.md)

### 2. 联网搜索和当前时间

- 每个请求都会带上当前日期和时间。
- 新闻、天气、比赛、比分、赛程、转会、伤病、政策、价格、热搜、“最新”“实时”等
  时效问题会自动启用千问联网搜索。
- 也可以显式搜索：

```text
/搜 今天有哪些重要足球新闻
/搜 杭州明天天气
```

- 要求模型优先使用带日期的可靠来源，不能把旧知识伪装成实时消息。
- 直接发送网页链接，或使用 `/网页 URL`，机器人会抓取正文，而不是只读搜索摘要。
- 网页正文会清洗、分段并加入知识库。

### 3. 多层记忆系统

机器人有三层记忆：

| 层级 | 内容 | 作用 |
|---|---|---|
| 短期上下文 | 每个会话最近 40 条消息 | 连续聊天 |
| 长期事实 | 从对话中提取的人物偏好、计划、关系等 | 跨联系人回忆 |
| 对话片段 | 用户原话和机器人当时回复 | 跨群聊回忆具体对话 |

此外还有后台反思层：

- 每 20 分钟检查一次新记忆。
- 检测到至少 1 条新记忆后进行关联分析。
- 会自动补扫尚未提取过的对话片段，不再完全依赖机器人当场回复。
- 提取范围包括人物偏好、承诺或约定、关系变化、长期项目、稳定个人信息和重要事件。
- 可以发现不同人物、地点、项目、兴趣之间的关联。
- 同一人物、分类和主题键出现新说法时，新记忆会自动取代旧记忆，并在冲突记录中保留
  “旧说法 → 新说法”，旧内容不会继续进入聊天上下文。
- 反思结果带置信度，并形成 `/成长` 可查看的成长笔记。
- 不保存或展示隐藏思维过程，不宣称机器人具有意识。
- 管理后台提供“立即反思”，QQ 管理员也可发送 `/反思` 强制执行。
- 反思结果会进入之后的回答上下文，不只是展示。
- 反思可以引用旧反思编号并原地更新，避免同一结论反复堆积。

管理后台的记忆时间线会显示每条记忆的状态、来源会话、原始对话片段、主题键和冲突；
支持编辑、软取代、合并，以及单独删除反思和成长笔记。

系统支持两种记忆策略：

```dotenv
# 默认保护：私密记忆只允许当事人使用
MEMORY_PRIVACY_PROTECTION=true

# 完整共享：不同联系人可以互相使用提取后的记忆
MEMORY_PRIVACY_PROTECTION=false
```

当前项目支持完整共享模式。关闭保护后，健康、财务、秘密等私密内容也可能影响其他
联系人的回答，只应部署在所有参与者都知情并同意的小圈子。

记忆管理命令：

```text
/记忆
/删记忆 编号
/忘记我
/成长
```

### 联系人画像

机器人会为每个联系人保存一份稳定但可更新的互动画像，包括偏好的回复长度、直接程度、
幽默感、适合的沟通方式和当前关系定位。每个联系人累计至少 5 条新对话后，后台会更新
一次画像；画像只总结聊天证据，不做心理诊断。

```dotenv
PROFILE_LEARNING_ENABLED=true
PROFILE_UPDATE_AFTER_MESSAGES=5
```

因此同一个人会保持前后一致的语气，不同联系人之间不会套用完全相同的回复模板。

### 向量记忆与知识库

长期记忆、跨群对话片段、上传文档和网页正文都会生成向量索引。回答时会同时使用：

- 当前会话最近消息
- 结构化长期记忆
- 跨会话对话片段
- 语义检索到的历史信息
- 文档页码或工作表片段

上传文件后会建立知识库，可以继续追问：

```text
/问文件 第三章讲了什么
/问文件 这个表格里最大的风险是什么
文档里关于进度延迟的结论在哪一页
```

回答会尽量标注文件名和页码、幻灯片、工作表或章节来源。

网页也可以主动收藏到知识库：

```text
/收藏网页 https://example.com/article
```

实例后台的“知识来源”页面可以查看文档和网页片段数量、原始位置并删除整个来源。

### 4. 图片与题目理解

- 普通截图自动切换到 `qwen3-vl-plus`。
- 可以读取题目、公式、图表、选项和图片中的文字。
- 可以附带要求，例如“只给答案”“给出详细步骤”。
- 单条消息默认最多处理 3 张图片，机器人侧不限制图片大小。
- QQ 商城表情、`mface` 和带 `emoji_id/key` 的表情包不会被误判成题目图片。

### 5. 文件解析与总结

支持：

- 文字型 PDF
- Word `.docx`
- PowerPoint `.pptx`
- Excel `.xlsx`
- CSV、TXT、Markdown
- 常见代码和配置文件

长文档会先分段提炼，再生成最终总结。可以要求提炼行动项、风险、会议纪要、汇报提纲
或表格分析。默认一次最多处理 3 个文件。

文字型 PDF 会直接提取文本；扫描版、图片型 PDF 和手写页面会按页渲染，再用
`qwen3-vl-plus` 做 OCR。旧格式 `.doc`、`.ppt`、`.xls` 仍需另存为新版格式。

### 6. 语音识别

- QQ 语音由 NapCat 转换为 WAV，再交给 `qwen3.8-omni-flash`。
- 默认返回语音转写。
- 可以要求总结、回答语音里的问题或提取待办。
- 支持 `/转写`、`/听写`、`/总结`、`/回答`。
- 支持 `/发语音 文本` 调用 `qwen-audio-3.1-tts-flash` 合成并发送语音。

### 7. 学习与工作工具

| 功能 | 命令 |
|---|---|
| 保存笔记 | `/记 标题 \| 内容` |
| 查看笔记 | `/笔记` |
| 搜索笔记 | `/查 关键词` |
| 删除笔记 | `/删笔记 编号` |
| 添加待办 | `/待办 内容` |
| 查看待办 | `/待办` |
| 完成待办 | `/完成 编号` |
| 添加提醒 | `/提醒 2026-11-05 09:00 复习第三章` |
| 查看提醒 | `/提醒` |
| 取消提醒 | `/取消提醒 编号` |

提醒按 `Asia/Shanghai` 时区解析，机器人每 15 秒检查一次。离线期间到期的提醒会在
机器人重启后补发。

常用的 AI 任务入口：

```text
/计划 两周内复习完线性代数
/总结 [粘贴材料]
/出题 线性代数第三章，出 5 道题
/翻译 [需要翻译的内容]
/润色 [需要修改的文字]
/解释 特征值和特征向量
```

### 8. QQ 互动

- 群聊和私聊都支持戳一戳：

```text
/戳
```

- 私聊也可以直接发“戳一戳”或“戳我”。
- 群聊可配置为“必须 @”或“智能参与”。免 @ 模式也不代表每条都回复。
- 智能参与会判断消息是否明确需要机器人，寒暄、道谢、群友互相聊天和短确认会被跳过。
- 机器人会参考最近群聊与自己的上一条消息，避免抢话或每次都成为最后一个发言者。
- 回复默认不引用；用户主动引用、发送媒体时才会引用原消息。
- 在“必须 @”模式下，直接引用机器人的回复可以继续追问，不必再次 @。
- 机器人会过滤 Markdown 星号、标题、表格和 emoji，输出适合 QQ 的纯文本。
- 长回复不会主动截断，会按 QQ 传输需要拆成多段。
- 管理员可以发送媒体：

```text
/发语音 你好，我是给她爱
/发图 https://example.com/image.png
/发文件 E:\files\report.pdf
/发表情 开心
```

机器人收到表情包时会保存可复用元数据。`/发表情` 会由模型结合最近对话和表情名称
选择匹配项，而不是随机发送；明显难过等不适合的语境不会强行发表情。
`/表情库` 可查看收藏数量、名称和使用次数。

实例后台可以对表情进行预览、分类、填写“适用场景”、停用和删除。模型选择表情时会
同时参考名称、分类、适用场景和最近对话，不再只凭表情名称猜测。

机器人也可以根据要求生成真实文件并直接发送：

```text
/生成图表 周一学习2小时，周二1.5小时，周三3小时
/生成文档 写一份本周学习复盘，包含目标和下周计划
/生成文件 生成一份可以导入表格的 CSV 打卡记录
```

也可以直接使用自然语言，不要求 `/` 命令：

```text
收集周杰伦《晴天》的歌曲资料，整理成 Word 发给我
把这些学习数据做成柱状图发我
把打卡记录导出成 CSV 给我
```

免艾特群聊会把这类明确的生成请求视为直接任务；“必须艾特”模式仍然要求 @。
歌词等受版权保护内容不会整首复制，会生成歌曲资料、分析、来源和短引用文档。

图表使用本地 Pillow 渲染为 PNG；文档生成 `.docx`；普通文件支持 Markdown、CSV 和
TXT。后台“内容生成”页面也能生成并直接下载。

## 管理网站

机器人启动后访问：

```text
http://127.0.0.1:8080/admin
```

管理网站提供：

- 运行模型、群聊、搜索和记忆状态
- 联系人列表与互动画像编辑
- 每个联系人的长期记忆、最近对话、待办和提醒
- 反思与成长笔记
- 记忆时间线、来源、冲突、编辑与合并
- 反思和成长笔记的编辑、删除
- 已收集表情包的预览、分类、适用场景和启停
- 文档与收藏网页的知识来源管理
- 模型调用次数、失败次数、延迟、Token 估算和可配置单价费用
- 各群沉默倾向和回复率，可单独重置学习结果
- 图表、文档和普通文件生成

网站只监听本机 `127.0.0.1`，不要直接暴露到公网。

### 登录式一站式控制台

完整控制台运行在独立的本机服务：

```text
http://127.0.0.1:8090/
```

双击 [启动控制台.cmd](启动控制台.cmd) 启动并打开浏览器。

首次访问会要求创建网站管理员账号。这个账号与 QQ 无关，QQ 密码不会进入网站或日志。
登录后自动进入控制台，可以：

- 新增和编辑 OpenAI 兼容 API 供应商
- 加密保存每个供应商的 API Key
- 选择千问、DeepSeek、OpenAI、OpenRouter、Ollama 或自定义接口
- 创建和管理多个本地机器人实例
- 配置实例端口、OneBot API、Token、供应商和数据库路径
- 启动、停止、重启机器人
- 打开实例自己的管理页面
- 下载包含全部实例数据库、配置和主密钥的加密备份
- 通过备份口令一键停止实例并恢复全部数据

API Key 和 OneBot Token 使用本地主密钥加密后写入 `data/control.db`。主密钥保存在
`.runtime/control-master.key`，不会提交 Git。保存后的 Key 只显示“已配置”，不会再
回传完整明文。

控制台的“全部实例备份与恢复”使用 PBKDF2 派生密钥和 Fernet 加密。备份包包含控制
数据库、实例数据库快照、`.env` 和控制台主密钥，必须使用至少 8 个字符的独立口令。
恢复前会把当前数据库快照保存到 `.runtime/pre-restore-*`，便于人工回滚。备份口令不会
保存到数据库，丢失后无法解密。

QQ 登录仍然通过 NapCat 二维码完成。控制台不提供 QQ 密码输入框。

```dotenv
CONTROL_HOST=127.0.0.1
CONTROL_PORT=8090
```

## 一键启动和关闭

### 启动

每次打开电脑后，双击：

[启动机器人.cmd](启动机器人.cmd)

脚本会自动：

1. 启动项目内的便携 NapCat。
2. 尝试用小号快速登录。
3. 等待 OneBot `3000` 端口上线。
4. 启动 Python 机器人。
5. 等待 `8080` 健康接口通过。

如果 QQ 登录态失效，脚本会打开 NapCat WebUI，扫码后自动继续。

### 关闭

双击：

[停止机器人.cmd](停止机器人.cmd)

只会关闭项目启动的机器人和便携 NapCat，不会关闭主 QQ。

### 群聊 @ 模式切换

- [群聊免艾特.cmd](群聊免艾特.cmd)：不强制 @，但由智能判断决定是否加入对话。
- [群聊必须艾特.cmd](群聊必须艾特.cmd)：只有 @ 机器人或引用机器人回复时才响应。

两个脚本都会直接修改 `.env` 并重启 Python 机器人，不会重启 NapCat。

智能参与参数：

```dotenv
GROUP_SMART_PARTICIPATION=true
GROUP_PARTICIPATION_MODEL=qwen3.8-flash
GROUP_MIN_REPLY_CONFIDENCE=0.65
```

## 安装

### 1. 安装依赖

```powershell
cd E:\Vibe\qq-smart-bot
uv sync --dev
```

### 2. 配置 NapCat

在 NapCat WebUI 中配置：

1. HTTP 服务端：`127.0.0.1:3000`
2. HTTP 客户端：`http://127.0.0.1:8080/onebot`
3. 两处消息格式都使用 `array`
4. 两处 Token 都与 `.env` 中的 `ONEBOT_TOKEN` 一致

可参考 [config/onebot11.example.json](config/onebot11.example.json)。

### 3. 配置千问 Key

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\set-qwen-key.ps1
```

脚本会隐藏输入，把 Key 写入本地 `.env`。`.env` 已被 Git 忽略，不会上传。

### 4. 启动

双击 [启动机器人.cmd](启动机器人.cmd)，或运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

## 数据与安全

- `.env`、API Key、聊天数据库、NapCat 和虚拟环境都不会提交到 Git。
- 聊天和长期记忆保存在本机 SQLite。
- 模型会收到完成请求所需的文字、图片、文档内容或音频。
- 图片和文件默认不长期保存原文件。
- 完整共享模式可能把一个人的信息用于另一个人的回答，需确保参与者知情。
- 不使用真实 QQ 密码；登录由 NapCat 扫码完成。
- 不要把 `.env`、API Key 或 QQ 登录凭据发给其他人。

## 已知限制

- 个人 QQ 自动化存在风控风险。
- 扫描 PDF 和手写 OCR 的准确率取决于清晰度，长 PDF 会消耗更多视觉 Token。
- 超大图片、文件和音频仍受 QQ、阿里云接口和本机资源限制。
- 联网搜索依赖模型服务可用性和第三方来源质量。
- 管理网站只适合本机使用，当前没有公网身份认证。
- TTS、媒体发送和表情包复用需要 NapCat 对应接口可用。
- 长期记忆和反思是模拟连续人格，不代表真正意识。
- 不同联系人的语气会基于历史调整，但核心人格和真实性边界不会自动改变。
- “给她爱”不会主动声称真人；被直接询问时会说明自己是 AI。
