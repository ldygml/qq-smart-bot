# 给她爱：QQ 智能聊天机器人

“给她爱”是一个运行在 Windows 本机、通过 NapCat 和 OneBot v11 接入 QQ 个人号的
AI 聊天机器人。它不是单纯的关键词回复脚本，而是一套包含聊天人格、群聊准入、长期
记忆、文件与图片理解、联网搜索、内容生成、表情管理、运行监控和本地控制台的完整
工具。

项目默认使用阿里云百炼千问系列模型，也支持 OpenAI、DeepSeek、OpenRouter、Ollama
以及其他 OpenAI 兼容 API。

> **重要风险提示**
>
> 使用个人 QQ 号自动收发消息不属于 QQ 官方机器人接入方式，存在账号风控风险。
> 建议只使用备用小号，不要批量加人、营销、刷屏或高频群发。需要长期稳定、公开合规
> 的机器人时，应优先使用 [QQ 开放平台](https://q.qq.com/) 的官方机器人能力。

## 项目定位

“给她爱”的目标不是做一个机械的 FAQ 机器人，而是做一个能长期使用、有记忆边界、
能参与日常学习与工作的 QQ 聊天对象：

- 私聊时像熟人聊天，普通话题短句、自然、有个人判断。
- 群聊时不抢话、不逐条回复、不总是成为最后一个发言者。
- 每个群可以独立设置发言频率、触发方式、模型和专属规则。
- 能记住不同联系人、不同群聊中出现过的人物、偏好、承诺、项目和关系变化。
- 能解析图片、文档、语音和表情包。
- 能联网搜索、读取网页、收藏知识来源。
- 能生成图片、Word 文档、CSV、Markdown、普通文件和代码项目。
- 能通过本地网页管理实例、API Key、记忆、表情、知识库、成本和群聊策略。
- 能加密备份和恢复全部实例数据。

机器人不会假装拥有真实线下生活，也不会宣称自己有意识。它被直接询问是否为 AI 时
会如实说明。

## 已实现功能

### 1. 接近真人的聊天人格

- 名称固定为“给她爱”，人格文件位于 [prompts/gexiai.md](prompts/gexiai.md)。
- 有脾气、有判断、说话直接，但不是无条件攻击或辱骂。
- 足球是个人兴趣，不会被强行塞进所有话题。
- 普通闲聊默认一到三句，不主动写标题、列表、总结或客服套话。
- QQ 回复会过滤 Markdown 星号、井号标题、表格和装饰性 emoji。
- 会根据联系人画像、当前会话历史、跨群片段和长期记忆调整表达。
- 支持 QQ 戳一戳和按语境引用消息。

### 2. 私聊与群聊

- 私聊可直接自然语言对话。
- 群聊支持“必须 @”和“免 @ 智能参与”。
- 智能参与会跳过寒暄、感谢、短确认、群友互相聊天和没有补充价值的话题。
- 可以识别 @、引用机器人消息、机器人名字、触发前缀和明确任务请求。
- 支持每个群独立配置，不会把一个群的策略套到另一个群。
- 每个群可以设置独立模型、冷却时间、每小时回复上限、最低置信度和专属提示词。
- 支持“避免连续收尾”，减少机器人成为每条对话最后一个发言者的情况。

### 3. 多层记忆

| 记忆层 | 内容 | 用途 |
|---|---|---|
| 即时上下文 | 当前会话最近 40 条消息 | 保持连续对话 |
| 对话观察 | 即使机器人没有回复，也记录有意义的群消息 | 后续补扫 |
| 长期事实 | 偏好、承诺、关系变化、长期项目、重要事件 | 跨会话回忆 |
| 对话片段 | 用户原话、机器人回复、时间和来源会话 | 回忆具体谈话 |
| 联系人画像 | 回复偏好、交流方式、关系定位 | 区分不同人的语气 |
| 反思与成长 | 跨人物和跨主题的推测、关联与成长笔记 | 持续更新认知 |

### 4. 自动记忆与反思

- 每 **20 分钟**检查一次尚未处理的对话和记忆。
- 自动提取人物偏好、承诺、关系变化、长期项目、稳定信息和重要事件。
- 同一人物的同一主题出现新说法时，新记忆自动取代旧记忆。
- 冲突保留“旧说法 → 新说法”，旧内容不再进入聊天上下文。
- 反思会参考已有反思和成长笔记，避免不断堆积重复结论。
- 支持手动 `/反思`。
- 不保存或展示隐藏思维过程，只保存可查看的结论、证据和置信度。

### 5. 图片、语音与文档

- 图片理解、截图题目、公式、图表和手写 OCR。
- 扫描版 PDF 按页渲染后通过视觉模型 OCR。
- 支持 PDF、DOCX、PPTX、XLSX、CSV、TXT、Markdown 和常见代码文件。
- 支持 QQ 语音转写、语音总结和语音问答；同一条消息中的多段语音会按顺序连续理解。
- 支持千问 TTS 生成 QQ 语音、情绪音色、动态语速和停顿，以及从管理页导出语音文件。
- 支持文档向量索引、跨文件问答和页码/章节引用。
- 支持网页正文抓取和知识库收藏。

### 6. 学习与工作工具

- 笔记：保存、查看、搜索、删除。
- 待办：添加、查看、完成。
- 提醒：按时间创建、查看、取消，离线期间到期的提醒会补发。
- AI 指令：计划、总结、出题、翻译、润色、解释、联网搜索。
- 文档问答：上传后继续追问，并标注来源位置。

### 7. 内容生成

- 图表：生成 PNG 柱状图、折线图或饼图。
- 文档：生成 Word `.docx`。
- 普通文件：生成 Markdown、CSV、TXT。
- 代码：生成 Python、JavaScript、TypeScript、HTML、CSS、Java、C/C++、Go、
  Rust、SQL、Shell 等文件。
- 多文件代码项目自动打包为 ZIP。
- 管理页可直接把文字合成为可下载的 WAV/MP3 语音文件。
- 支持固定命令和自然语言触发。
- 内容生成会先做事实检索和独立审校；代码会先做本地语法检查。
- 文件名统一为单一正确扩展名，不会产生 `文件.md_时间戳.md` 或 `报告.docx.docx`。

### 8. 表情包

- 收到 QQ 商城表情、`mface` 或 `sub_type=1` 的图片型动画表情时会自动收藏。
- 即使 NapCat 没有提供 `emoji_id/key`，也会用图片地址生成唯一收藏标识。
- 新表情会在后台自动生成分类和适用场景；后台也提供“自动整理未分类表情”。
- 不把表情包误判为普通题目图片。
- 自动用视觉模型识别画面、文字和梗，并生成“无语、嘲讽、庆祝”等标签。
- 结合聊天语境、表情标签、成员禁忌、联系人画像和关系备注决定是否发送。
- 可以在网页中预览、分类、填写适用场景、停用和删除。
- 没有合适表情时不强行发送。

### 9. 群聊行为学习

- 记录每个群的观察消息数、候选回复数、跳过数和回复数。
- 根据普通消息跳过比例调整沉默倾向。
- 刚发言后进入独立冷却时间。
- 支持每群每小时回复上限。
- 支持每群单独清空行为学习记录。
- 每个群可设置允许、禁止或仅管理员戳一戳。
- 支持成员专属称呼、禁忌和“不接受玩笑”偏好。
- 支持活跃时段、屏蔽关键词和 10 分钟重复消息过滤。
- 支持群 FAQ、规则、公告、常用资料和定期公告总结。
- 支持在 QQ 中通过 `/群文件` 查看群文件，也可在实例管理页和登录控制台读取群文件目录。
- 群内上传文件使用独立群知识库，不会检索到其他群的文件。
- 新成员入群时可以按该群欢迎语自动介绍。

### 10. 登录式控制台与加密备份

- 网站管理员账号与 QQ 账号完全无关。
- 支持多个 OpenAI 兼容 API 供应商。
- API Key 和 OneBot Token 加密保存。
- 支持多个本地机器人实例的启动、停止、重启和删除。
- 支持实例记忆维护和单群设置。
- 支持全部实例的加密备份与恢复。
- 不提供 QQ 密码输入框，QQ 登录仍由 NapCat 扫码完成。
- 可为聊天、代码、视觉、OCR、语音识别、TTS、向量和反思分别配置
  主供应商、模型和备用链。
- 控制台展示每个模型的成功率、延迟、Token 和费用，并记录最近错误。

### 11. 对话质量评测

- 记录机器人回复以及用户是否继续追问、纠正或忽略。
- 自动识别答非所问、重复、过长、语气不自然和群聊乱插话。
- 支持手动触发质量评测。
- 支持用历史消息回放不同人格提示词和模型，对比候选回复。
- 低分回复的改进建议会按私聊/群聊隔离，并注入下一次回复，不只是留在后台面板。

### 12. 自然聊天节奏

- 可配置随机打字延迟、长回复分段和发送间隔。
- 连续快速发来的几条私聊会先合并理解，再回一次，不对每句话机械逐条回复。
- 检测最近重复的开场和口头禅，要求下一次换一种自然表达。
- 普通问候、温柔请求和正常分享不会强行加冷嘲；只有语境确实需要时才犀利。
- 根据活跃时段、群消息密度和用户情绪调整回复长度。
- 长时间未聊天后不会生硬续接旧话题。
- 记忆中的承诺和项目可在合适时间被自然追问。

```text

NapCat + QQNT
   │  OneBot v11 HTTP
   ├──────────────► http://127.0.0.1:8080/onebot
```

| NapCat WebUI | `http://127.0.0.1:6099/webui` | QQ 扫码登录和 OneBot 配置 |

## 快速开始

### 1. 安装依赖

```powershell
cd E:\Vibe\qq-smart-bot
uv sync --dev
```

### 2. 配置模型 API

推荐通过隐藏输入的脚本写入 Key：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\set-qwen-key.ps1
```

也可以直接编辑 `.env`：

```dotenv
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
CASUAL_MODEL=qwen3.8-flash
LLM_API_KEY=你的_API_Key
```

`.env` 已被 Git 忽略，不要手动提交或发送给其他人。

### 3. 配置 NapCat

在 NapCat WebUI 中确认以下配置：

1. HTTP 服务端监听 `127.0.0.1:3000`。
2. HTTP 客户端上报到 `http://127.0.0.1:8080/onebot`。
3. 消息格式使用 `array`。
4. HTTP 服务端和 HTTP 客户端使用同一个 Token。
5. Token 与 `.env` 中的 `ONEBOT_TOKEN` 完全一致。

示例文件见 [config/onebot11.example.json](config/onebot11.example.json)。

### 4. 登录 QQ

首次运行或登录状态失效时：

1. 启动机器人脚本。
2. 脚本打开 NapCat WebUI。
3. 使用 QQ 小号扫码登录。
4. 等待 OneBot `3000` 端口和机器人 `8080` 端口上线。

### 5. 启动机器人

双击 [启动机器人.cmd](启动机器人.cmd)，或运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

启动成功后访问：

```text
http://127.0.0.1:8080/admin
```

### 6. 启动登录控制台

双击 [启动控制台.cmd](启动控制台.cmd)，或运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\control.ps1
```

首次访问 `http://127.0.0.1:8090/` 时创建网站管理员账号。该账号只用于本地控制台，
与 QQ 密码无关。

## QQ 中的使用方法

### 私聊

直接发送自然语言即可：

```text
今天有点累，不想学习
帮我解释一下特征值
这张图里第三题怎么做
记住我下周三要去杭州
```

### 群聊

群聊有两种主要模式：

1. **必须 @**：普通自然语言必须 @ 机器人才会进入判断。
2. **免 @ 智能参与**：机器人判断是否值得插话，不会每条都回复。

也可以使用触发前缀：

```text
/ai 这个报错怎么解决
/问 总结一下刚才讨论的方案
```

在“必须 @”模式下，直接引用机器人的回复可以继续追问，不必再次 @。

### 上传图片

直接发送截图，并可附上要求：

```text
只给最终答案
给出详细步骤
先识别图片文字，再解释
```

### 上传文件

发送 PDF、DOCX、PPTX、XLSX、CSV、TXT 或 Markdown 文件，机器人会自动解析和总结。

上传后继续追问：

```text
/问文件 第三章的核心结论是什么
/问文件 这个表格里最大的风险是什么
/问文件 进度延迟相关内容在第几页
```

### 发送语音

直接发送 QQ 语音，默认进行转写。可以在语音后说明任务，例如：

```text
总结这段语音
回答语音里的问题
提取里面提到的待办事项
```

## 记忆与成长

### 短期上下文

每个会话默认保留最近 40 条消息。`/重置`只清空当前会话的短期上下文，不删除长期记忆。

### 长期记忆

机器人会从对话中提取以后仍有用的事实，例如：

- 稳定偏好和习惯
- 明确承诺和约定
- 关系变化
- 正在进行的长期项目
- 重要事件
- 稳定个人信息

玩笑、角色扮演、假设和临时称呼不应被当作稳定事实。

### 对话观察

即使机器人在群里没有回复，有意义的群消息也会进入待处理观察队列。20 分钟反思任务
会补扫这些消息，以免只有“机器人回复过的内容”才会被记住。

### 冲突与更新

系统使用“人物 + 分类 + 主题键”识别同一主题：

```text
旧：住在杭州
新：住在上海
结果：旧记忆标记为已取代，新记忆成为有效记忆
```

旧说法仍保留在时间线中供追溯，但不会继续作为当前事实进入聊天上下文。

记忆增强功能：

- 为承诺、项目和关系变化设置跟进时间。
- 聊天时仅在合适语境下自然询问到期事项。
- 根据画像、记忆和最近对话生成联系人近况摘要。
- 冲突以待审核状态展示，可保留新说法、恢复旧说法或忽略提醒。
- 导出完整记忆 JSON、导入备份，以及按时间范围批量清理。

### 批量删除记忆

实例后台和登录控制台都提供两种彻底删除操作：

- “删除此人的全部记忆”：清除该联系人的画像、长期记忆、对话片段、未回复观察、
  相关反思/成长、冲突事件、短期聊天和记忆向量。
- “删除全部人的全部记忆”：清空所有联系人以及上述全部记忆数据。

以下数据和配置不会被删除：

- 笔记
- 待办
- 提醒
- 群聊设置
- 文件知识库和收藏网页
- API 供应商与实例配置

批量删除不可撤销，操作前会有二次确认。

### 联系人画像

每个联系人累计至少 5 条新对话后，后台会更新互动画像。画像只总结聊天中可观察的
互动倾向，不做心理诊断。

### 记忆隐私

```dotenv
# 私密记忆仅当事人可用
MEMORY_PRIVACY_PROTECTION=true

# 不同联系人可以互相使用提取后的记忆
MEMORY_PRIVACY_PROTECTION=false
```

完整共享模式适合所有参与者知情并同意的小圈子。不要把包含健康、财务、秘密或私人冲突
的共享记忆部署到不可信人群。

## 单群独立管理

网站提供两层群聊配置：

1. 全局默认设置。
2. 每个 QQ 群自己的独立设置。

新群第一次出现时会复制全局设置；之后各群互不影响。

群名称会优先从 NapCat 的 `get_group_list` 接口自动读取，并使用 QQ 群原名初始化。
名称可以在两个网页中直接修改；修改过的自定义名称不会被后续自动同步覆盖。如果暂时
无法取得 QQ 群名，后台会显示“群 + 群号”，也可以手动填写。

实际优先级从高到低为：

```text
ENABLE_GROUP 总开关
    > 当前群的独立配置
    > 全局群聊默认配置
```

“群聊免艾特”和“群聊必须艾特”脚本是批量操作，会同时覆盖全局默认和所有已有群的
对应设置。只想改变一个群时，应使用网页中的单群管理。

每个群可以单独设置：

- 是否启用
- 是否必须 @
- 是否智能参与
- 是否学习沉默倾向
- 最低回复置信度
- 回复冷却秒数
- 每小时回复上限
- 群聊参与模型
- 触发前缀
- 是否按语境引用
- 引用机器人是否算 @
- 是否允许自动发表情
- 是否避免连续收尾
- 戳一戳策略与引用策略
- 活跃时段和屏蔽关键词
- 随机打字延迟、分段回复
- 新成员欢迎语和公告总结周期
- 独立 FAQ、规则、公告、常用资料和成员称呼/禁忌
- 本群专属发言规则

示例专属规则：

```text
这个群只回答技术问题，不主动接闲聊。
一次最多回答两句话。
不要使用讽刺语气。
```

入口：

- 实例后台：`http://127.0.0.1:8080/admin` →“群聊与成本”
- 登录控制台：`http://127.0.0.1:8090/` → 在线实例 →“群聊设置”

## 内容生成

### 自然语言触发

不需要 `/` 命令：

```text
把这些学习数据做成柱状图发给我
整理一份本周学习复盘，发 Word 给我
把打卡记录导出成 CSV
写个 Python 脚本读 CSV 并算平均值
实现一个待办网页，把完整代码项目发我
先联网搜索并核对最新信息，再整理成 Word 发给我
```

免 @ 群聊会把明确的生成请求视为直接任务；开启“必须 @”后仍然需要 @。

### 事实质量控制

歌曲、人物、新闻、政策、数据等任务会：

1. 先通过搜索模型收集结构化事实。
2. 每条事实要求附带来源链接。
3. 起草文档。
4. 使用独立审校步骤删除材料没有直接支持的日期、数字、奖项、销量、引语和结论。
5. 只保留核对材料中实际出现的链接。
6. 去除重复段落和空泛的“未核实”章节。

如果明确说“先联网搜索”“查证后再生成”，系统会强制进入检索流程。搜索失败、没有
返回可核实事实或没有可用来源时会停止生成并报错，不会跳过核对继续编造。

实例后台的“内容生成”页面也提供“生成前强制联网搜索并核对来源”选项。

联网检索和模型审校仍然不能保证 100% 正确。用于论文、法律、医疗、财务或正式发布前，
应人工核查原始来源。

### 文件命名

系统会先移除模型返回的旧扩展名，再添加正确扩展名。

正确示例：

```text
晴天.docx
学习复盘.docx
打卡记录.csv
main.py
todo_web.zip
```

不会生成：

```text
晴天.md_20261104.md
报告.docx.docx
代码.cpp.txt
```

已有历史文件不会自动改名或删除，以免误删用户数据。

### 代码文件

- 单文件会直接发送并保留正确扩展名。
- 多文件项目自动打包 ZIP。
- 可以包含源码、README、依赖文件和配置文件。
- Python、JSON、TOML 会在本地先做语法检查。
- 语法错误时会自动请求模型修复一次。
- 机器人只生成文件，不会自动执行代码。
- 模型生成的代码仍应人工审阅后再运行。

### 歌词与版权文本

机器人不会主动抓取并完整输出现有歌曲的受版权保护歌词。歌词类请求会生成歌曲资料、
主题、结构和来源分析。

如果你提供自己创作或已获授权的文本，机器人可以按原内容整理和转换文件格式。

## 故障排查

### 机器人不回复私聊

1. 检查 `http://127.0.0.1:8080/healthz` 是否返回 `ok:true`。
2. 检查 `.env` 中的 `PRIVATE_ALLOWLIST` 是否排除了当前 QQ。
3. 检查 `OWNER_QQ` 和管理员命令权限。
4. 查看 `.runtime/bot.stderr.log`。

### 机器人在群里不回复

1. 检查全局 `ENABLE_GROUP`。
2. 打开单群管理，确认该群没有停用。
3. 检查该群是否设置为“必须 @”。
4. 检查群白名单。
5. 查看该群冷却时间、每小时上限和沉默倾向。
6. 在“测试”群中 @ 机器人测试。

### 模型超时或 429

- 检查 API Key 和余额。
- 检查 `LLM_BASE_URL`。
- 如果使用本机代理，正确设置 `LLM_TRUST_ENV=true`。
- 检查 `LLM_TIMEOUT_SECONDS`。
- 在控制台中查看失败次数和延迟。

### NapCat 或 OneBot 连接失败

- 确认 `127.0.0.1:3000` 可访问。
- 检查 HTTP 服务端、HTTP 客户端和 `.env` 中的 Token 是否一致。
- 确认上报路径是 `/onebot`，消息格式是 `array`。
- 登录失效时重新打开 `http://127.0.0.1:6099/webui` 扫码。

### 控制台无法访问

```powershell
powershell -ExecutionPolicy Bypass -File .\control.ps1
```

如果仍失败，查看：

```text
.runtime/control.stderr.log
```

### 文件生成失败

- 检查 `MEDIA_SEND_ENABLED=true`。
- 检查模型 Key、余额和超时。
- 查看实例后台的调用错误记录。
- 代码文件语法检查失败时不会发送坏文件，可补充更明确的需求后重试。
- 代码主模型超时后会自动尝试备用模型；如果两个模型都失败，才会返回错误。

### 文件名看起来不正确

新版本会去除重复扩展名。旧版本已经生成的文件不会被自动删除或改名，可以在
`data/generated/` 中手动整理。

### 表情库为空

先让其他 QQ 用户或测试小号给机器人发送几个商城表情。机器人收到后才会建立表情库。

### 反思没有结果

- 确认 `SHARED_MEMORY_ENABLED=true`。
- 确认 `REFLECTION_ENABLED=true`。
- 在网站点击“立即反思”。
- 检查聊天中是否存在可长期保存的事实。
- 查看模型错误和后台反思记录。

## 已知限制

- 个人 QQ 自动化始终存在平台风控风险。
- 管理网站目前定位于本机使用，不是公网多租户 SaaS。
- 登录控制台并不会替每个实例自动创建独立的 NapCat；仍需配置对应 OneBot 地址。
- 不同模型供应商对视觉、OCR、搜索、TTS 和嵌入接口的支持程度不同。
- 联网搜索和文档审校无法保证第三方来源本身完全准确。
- 长 PDF、扫描件和高清图片会消耗较多视觉 Token。
- QQ、模型 API 和 NapCat 本身仍有文件大小、频率和接口限制。
- 长期记忆是数据库中的可追踪记录，不是人类意识或隐藏思维过程。
- 现有历史生成文件不会自动重命名。
